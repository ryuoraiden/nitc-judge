# Build plan

Locked decisions: local Flask + gcc (not Piston, not Docker); problems as folders
on disk with sqlite holding only progress; three problem modes (`program`,
`function`, `py-*`).

## Phases

- [x] **0 - Skeleton.** Flask app, content loader, gcc runner, run/submit, verdicts,
      UI. Sandbox bounds wall-clock time and output bytes; Windows crash dialogs
      suppressed so a segfault reports as RE rather than TLE.
- [x] **1 - Mode B.** Hidden `harness_main.c` compiled against the student's `.c`,
      read-only header tab, three-column diff with first-difference highlighting,
      hidden tests that show a verdict but not their data.
- [x] **2 - S3 Week 4 content.** 21 problems: Stack (3), Queue (3), Heap (4),
      BFS (6), Dijkstra (5), ending at Practice Q1, Q2 and Q4.
- [ ] **3 - Progress surfacing.** Models and gating already exist; the dashboard
      shows only the review queue. Still to build: attempt history view, weak-topic
      breakdown, time-to-solve stats.
- [ ] **4 - S1/S2 content.** ~45 micro-problems over arrays, strings, structs,
      recursion, linked lists, trees, BST.
- [ ] **5 - Learning layer.** Blank-slate re-solve, complexity MCQ after AC (fold in
      the existing `NITC_Code_Quiz.html` questions), prereq gating in the UI.
- [ ] **6 - MAD 1 track.** `py-cli` / `py-flask` / `py-html` runners, pytest
      harness, BeautifulSoup structural assertions, Weeks 2-6 content.
- [ ] **7 - Leak checking.** Linked `alloc_track.c` wrapping malloc/free, so the
      linked-list and tree problems can grade `free` discipline. Needed because
      this toolchain has no sanitizers.

## Content rule

Every multi-function lab problem becomes 3-5 single-function micro-problems of
6-10 minutes each, then one full integration problem. Provided-for-you helpers go
in `extra/` so each rung tests exactly one idea.

## Verification rule

Reference solutions are the oracle and they came from vibe-coded originals, so
nothing ships on trust: expected outputs are generated by running, references are
cross-checked against the originals and against independent reimplementations, and
non-obvious algorithmic claims are fuzzed against brute force.
